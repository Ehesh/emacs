This is a *writing-first scholarly environment*, built on [[https://github.com/jamescherti/minimal-emacs.d][minimal-emacs.d]].

* How this config is structured
:PROPERTIES:
:CUSTOM_ID: structure
:END:

minimal-emacs.d gives us two files we *never edit* — =early-init.el= and
=init.el=. They load our own files in a fixed order:

: early-init.el  ->  pre-early-init.el  ->  post-early-init.el
: init.el        ->  pre-init.el  ->  (packages)  ->  post-init.el

Everything in *this* file tangles into =post-init.el= (the last file loaded),
so it runs after minimal-emacs.d's defaults and package setup are in place.

*The golden rule:* edit only this =Config.org=. Never hand-edit the generated
=.el= files — they are overwritten on every tangle. Saving this file
auto-tangles it (see below).

*Portability:* the =:tangle post-init.el= target above is a *relative* path, so
it always resolves next to this file regardless of how Emacs was launched or
which OS you're on. (Absolute =~/.emacs.d/...= targets are fragile on Windows:
=~= only points here when Emacs is launched without =HOME= set, e.g. from the
Start menu, but not from a shell.)

This is the *boot-first minimal slice*: clean, portable, sane defaults, and a
modern-looking theme placeholder. The full look (nano), packages, meow, Org
tooling, etc. layer on in later passes. The previous large config is preserved
in =Config.org.bak= to salvage from.

* Auto-tangle on save
:PROPERTIES:
:CUSTOM_ID: auto-tangle
:END:

Re-tangle =Config.org= automatically whenever it is saved. Implemented with a
plain =after-save-hook= (no external package) so it works on a fresh clone
before anything is installed. Matches by filename, so it is independent of how
=~= or =user-emacs-directory= happen to resolve.

#+begin_src emacs-lisp
(defun e6/auto-tangle-config ()
  "Tangle the Emacs `Config.org' when it is saved."
  (when (and buffer-file-name
             (string-equal (file-name-nondirectory buffer-file-name)
                           "Config.org"))
    (let ((org-confirm-babel-evaluate nil)
          (message-log-max nil)
          (inhibit-message t))
      (require 'org)
      (org-babel-tangle))))

(add-hook 'after-save-hook #'e6/auto-tangle-config)
#+end_src

* Look & feel
:PROPERTIES:
:CUSTOM_ID: look
:END:

This is *Pass 1: the look* — a genuinely modern, calm, typeset-document feel
(nano aesthetic), not "90s Emacs". It layers, so we keep our own keys and
packages:

- *fontaine* — font presets (FiraCode mono + Gentium prose)
- *nano-theme* — the colour palette
- *nano-modeline* — a minimal modeline
- *spacious-padding* — airy internal borders/padding
- *mixed-pitch* — prose in Gentium, code/tables in FiraCode
- *org-modern* + *org-appear* — Org reads like a document

All installs are handled by minimal-emacs.d's =use-package-always-ensure=.

** Fonts — fontaine
:PROPERTIES:
:CUSTOM_ID: fontaine
:END:

fontaine defines named font presets and applies them to the =default=,
=fixed-pitch=, and =variable-pitch= faces. Missing fonts fall back to the Emacs
default automatically (no error), so this is safe on a machine without them.

#+begin_src emacs-lisp
(use-package fontaine
  :if (display-graphic-p)
  :config
  (setq fontaine-presets
        '((default
           :default-family "FiraCode Nerd Font"
           :default-height 120
           :fixed-pitch-family "FiraCode Nerd Font"
           :variable-pitch-family "Gentium Plus"
           :variable-pitch-height 1.15)))
  ;; Persist and restore the last-used preset across sessions.
  (fontaine-mode 1)
  (fontaine-set-preset (or (fontaine-restore-latest-preset) 'default)))
#+end_src

* Editing core
:PROPERTIES:
:CUSTOM_ID: editing-core
:END:

*Pass 2* — how you actually drive Emacs: [[https://github.com/meow-edit/meow][meow]] modal editing, a leader
key that opens [[info:transient][transient]] menus, Magit, and an "AI pipe" helper. Layout is
tuned for *prose/navigation*, not coding, and stays modal-agnostic so a future
swap (e.g. to meep) is one contained change.

*How meow works (read this):* buffers open in *NORMAL* state, where letter keys
are commands, not text. Press =i= to *insert* (type normally), =ESC= to return
to normal. =SPC= is the *leader* — =SPC= then a letter opens a menu (which-key
shows the options). Escape hatch: =M-x meow-global-mode= toggles the whole thing
off if you ever want plain Emacs.

** AI pipe helper
:PROPERTIES:
:CUSTOM_ID: ai-pipe
:END:

Send the region (or whole buffer) to an external CLI agent on stdin and get the
result back — a tidy wrapper over =shell-command-on-region= (=M-|=). Set
=e6/ai-cli-command= to your CLI. By default the output opens in a side buffer;
with a prefix arg (=C-u=) it *replaces* the region in place.

#+begin_src emacs-lisp
(defcustom e6/ai-cli-command ""
  "Default external CLI for `e6/pipe-to-ai'. It receives text on stdin.
For example \"llm\" or \"claude -p\". Leave empty to be prompted each time."
  :type 'string
  :group 'e6)

(defun e6/pipe-to-ai (beg end &optional replace)
  "Pipe the region (BEG END), or the whole buffer, to a CLI agent.
Without a prefix arg, show the output in *AI Output*; with a prefix arg
REPLACE the region/buffer in place."
  (interactive
   (if (use-region-p)
       (list (region-beginning) (region-end) current-prefix-arg)
     (list (point-min) (point-max) current-prefix-arg)))
  (let ((cmd (read-shell-command "Pipe to: " e6/ai-cli-command)))
    (if replace
        (shell-command-on-region beg end cmd nil t)
      (shell-command-on-region beg end cmd "*AI Output*")
      (with-current-buffer "*AI Output*"
        (view-mode 1))
      (display-buffer "*AI Output*"))))
#+end_src

* Completion stack
:PROPERTIES:
:CUSTOM_ID: completion
:END:

*Pass 3* — the minibuffer + in-buffer completion stack, cleaned up from the old
config (all =counsel/ivy= removed). The layers:

- *vertico* — vertical minibuffer UI
- *orderless* — space-separated fuzzy matching
- *marginalia* — rich annotations next to candidates
- *consult* — enhanced search/navigation commands (powers =SPC ,=, =SPC /=,

- *embark* — contextual actions on the thing at point (=C-.=)
- *corfu* + *kind-icon* — in-buffer completion popup (manual =TAB=, so it never
  interrupts prose)
- *cape* — extra completion-at-point sources

** Spellcheck — jinx (+ portable fallback)
:PROPERTIES:
:CUSTOM_ID: spell
:END:

[[https://github.com/minad/jinx][jinx]] (enchant-based, fast, multi-language) is excellent but needs libenchant +
a C toolchain — practical on *Linux/macOS*, not Windows. So jinx is OS-guarded;
on Windows (or without enchant) we fall back to built-in =flyspell= *if* a
speller (hunspell/aspell) is installed. Either way, =SPC r s= corrects a word.

#+begin_src emacs-lisp
(use-package jinx
  :if (and (not e6/windows-p) (executable-find "enchant-2"))
  :hook ((text-mode . jinx-mode)
         (org-mode  . jinx-mode))
  :custom
  (jinx-languages "en_US es")
  :bind ("M-$" . jinx-correct))

;; Portable fallback when jinx is unavailable.
(when (or e6/windows-p (not (executable-find "enchant-2")))
  (setq ispell-program-name (or (executable-find "hunspell")
                                (executable-find "aspell")))
  (when ispell-program-name
    (add-hook 'text-mode-hook #'flyspell-mode)))

(defun e6/spell-correct ()
  "Correct the word at point with whatever speller is active."
  (interactive)
  (cond ((bound-and-true-p jinx-mode)      (call-interactively #'jinx-correct))
        ((bound-and-true-p flyspell-mode)  (call-interactively #'flyspell-correct-word-before-point))
        (t                                  (call-interactively #'ispell-word))))
#+end_src

** One-time setup (do this later, yourself)
:PROPERTIES:
:CUSTOM_ID: email-setup
:END:

The Emacs package above is ready; it needs the =himalaya= CLI and a configured
Gmail account. *You'll do these steps — they involve a password, which I won't
touch:*

1. *Install the CLI:* Windows =scoop install himalaya= (or =cargo install
   himalaya=); Linux via your package manager or =cargo=. Check with
   =himalaya --version=.
2. *Google side:* turn on *2-Step Verification*, then create an *App Password*
   (Google Account → Security → App passwords). This 16-char password is used
   instead of your real one.
3. *himalaya config* at =~/.config/himalaya/config.toml= (himalaya can generate
   it with =himalaya account configure gmail=). A minimal Gmail account looks
   like:

   #+begin_example
   [accounts.gmail]
   default = true
   email = "uni.elihu@gmail.com"
   display-name = "Elihu SoNy"

   backend.type = "imap"
   backend.host = "imap.gmail.com"
   backend.port = 993
   backend.login = "uni.elihu@gmail.com"
   backend.auth.type = "password"
   # Use the Gmail APP PASSWORD here (or a keyring/command — see himalaya docs)
   backend.auth.raw = "PASTE-APP-PASSWORD"

   message.send.backend.type = "smtp"
   message.send.backend.host = "smtp.gmail.com"
   message.send.backend.port = 465
   message.send.backend.login = "uni.elihu@gmail.com"
   message.send.backend.auth.type = "password"
   message.send.backend.auth.raw = "PASTE-APP-PASSWORD"
   #+end_example

   Prefer not to store the password in plain text? himalaya supports
   =auth.type = "command"= (e.g. reading from =pass=, the Windows Credential
   Manager, or =authinfo.gpg=) — see the himalaya docs. OAuth2 is intentionally
   *not* used here (fragile in himalaya today); the app password is the reliable
   path.
4. Test on the CLI: =himalaya envelope list=. Then in Emacs: =SPC m=.
