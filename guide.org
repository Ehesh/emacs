#+TITLE: E6's Emacs — Starter Guide
#+STARTUP: overview
#+OPTIONS: toc:2

A hands-on guide to *actually using* this Emacs. Open it any time with =SPC n G=.
Everything here works in this config as shipped.

* First: how to move and type (meow)
:PROPERTIES:
:CUSTOM_ID: meow
:END:

Buffers start in *NORMAL* state — letters are commands, not text.

- =i= → *insert* (now you type normally).  =ESC= → back to normal.
- Move: =h j k l= (left/down/up/right), =w=/=b= (word forward/back),
  =e= (next word), =x= (select whole line).
- Select then act: =x= (line) then =s= (kill) or =y= (copy) or =c= (change).
- Undo: =u=.  Search: =/= (leader) then type; =n= repeats a search.
- Save: =C-x C-s=.  Kill buffer: =SPC k= (or =SPC b k=).
- *Panic button:* =M-x meow-global-mode= turns modal editing off entirely.
- Full layout: =M-x meow-cheatsheet=.

* The leader (SPC) — your command palette
:PROPERTIES:
:CUSTOM_ID: leader
:END:

In NORMAL state press =SPC=, then a key. Single-action keys run immediately;
*menu keys open a popup menu* (a "transient") listing its own sub-keys — read
that popup and press the letter you want. (Transient popups are separate from
which-key, which shows only the top-level =SPC= keys.)

| Key       | Does                                                     |
|-----------+----------------------------------------------------------|
| =SPC SPC= | Run any command (M-x)                                     |
| =SPC .=   | Find file                                                |
| =SPC ,=   | Switch buffer                                            |
| =SPC /=   | Search this buffer                                       |
| =SPC c=   | Capture a note (menu: i/f/p/b)                           |
| =SPC k=   | Kill current buffer                                      |
| =SPC j=   | Jump to the active minibuffer (also =C-c j=)             |
| =SPC \vert= | Send region/buffer to your AI CLI (pi)                 |
| =SPC p=   | *Project* commands (switch/find/grep…)                   |
| =SPC b=   | Buffers menu (switch, *save* =s*, *kill* =k*, revert…)   |
| =SPC f=   | Files menu (find, recent, Dirvish, save)                 |
| =SPC g=   | Git menu → =g= opens Magit status                        |
| =SPC l=   | Launch & convert menu (exports, marimo, services)        |
| =SPC n=   | Notes menu (capture, inbox, agenda, sprints, guide)      |
| =SPC r=   | Research menu (citations, PDF, IPA, spell, ling examples)|
| =SPC m=   | Email (himalaya)                                         |
| =SPC s=   | Search menu (line, ripgrep, grep, imenu…)                |
| =SPC t=   | Toggles (wrap, numbers, theme, olivetti, timer, read-aloud)|
| =SPC h=   | Help (describe function/variable/key/mode)               |
| =SPC w=   | Windows menu (split, other, balance…)                    |

So "open Magit" is =SPC g= (the git popup appears) then =g=. "Save the buffer"
is =SPC b= then =s=, or just =C-x C-s=.

* Org basics
:PROPERTIES:
:CUSTOM_ID: org-basics
:END:

** Headings and folding
=*=, =**=, =***= make headings. =TAB= folds/unfolds a heading;
=S-TAB= cycles the whole document.

** TODO states (Emotional Sprints)
Instead of TODO/DONE, tasks are classed by how they *feel*. Type =* FIRE Thing=
(or PLAY/BORING/APPROACH). On the heading, =C-c C-t= picks a state; or press the
fast key: =f= FIRE, =a= APPROACH, =b= BORING, =p= PLAY, =d= DONE. See the
Sprints workflow below.

** Links
=C-c C-l= inserts a link; =RET= on a link follows it.

** Emphasis
=*bold*=, =/italic/=, ==code==, =~verbatim~=. Markers hide until the cursor is on
the word (org-appear).

** Source blocks
Type =<s= then =TAB= (org-tempo) to expand a =#+begin_src … #+end_src= block.

* Capture — never lose a fleeting idea
:PROPERTIES:
:CUSTOM_ID: capture
:END:

=SPC c= (or =C-c c=), then pick — *low friction, just spit it out*:
- =i= — Inbox: a raw idea → under *Inbox* in =inbox.org=.
- =f= — FIRE task · =p= — PLAY task · =b= — BORING task → under *Tasks*.

Type it, =C-c C-c= to save (=C-c C-k= cancels). Don't file/tag/schedule — just
dump and clear your screen. Open the inbox with =SPC n i=.

* The Emotional Sprints workflow (ADHD-friendly)
:PROPERTIES:
:CUSTOM_ID: sprints
:END:

The idea: don't sort tasks by project, sort by *energy*. Then when a hard task
(FIRE) feels impossible, downshift to a tiny PLAY/BORING win to start the
dopamine loop.

- Capture freely with =SPC c= (see above) — everything lands flat in =inbox.org=.
- Open the *dashboard* with =SPC n s= (stacks tasks by sprint, not by clock):
  ⚡ FIRE · 📅 APPROACH · 🎨 PLAY · 🪵 BORING.
- Resisting the FIRE list? Jump to PLAY or BORING, find a 2-minute task, and hit
  =d= (mark DONE) for instant feedback. Then move up.

Start a Pomodoro on whatever you pick: =SPC t p= → =p= (25 min work / 5 break).

* Tables, glossing & linguistic examples
:PROPERTIES:
:CUSTOM_ID: tables
:END:

Start a table with a header row of pipes and press =TAB=:

: | Form | Gloss | Notes |
: |------+-------+-------|

=TAB= moves cell to cell (adding rows); =|-= then =TAB= draws a rule. Columns are
pixel-aligned by valign; toggle with =M-x valign-mode= if a huge table lags.

For *pandoc-ling* interlinear examples (in Markdown/QMD), use =SPC r l=:
- =e= a numbered example · =i= a 4-line interlinear (header/source/gloss/free) ·
  =l= a labeled example · =r= a cross-reference =[@label]=.
To render them, set =e6/pandoc-ling-filter= to your =pandoc-ling.lua= (see the
README), then export.

* Assembling notes by reference (transclusion)
:PROPERTIES:
:CUSTOM_ID: transclusion
:END:

Add a line like:

: #+transclude: [[file:chapter1.org::*Method]]

then =SPC n t= to render it (=SPC n T= toggles the whole buffer). Edits stay in
the source file — good for stitching a thesis from section files.

* Images & feeds
:PROPERTIES:
:CUSTOM_ID: media
:END:

- *Image:* copy it, then =SPC n d= drops it in (saved under =images/= by your
  notes). Dragging a file into the buffer also works.
- *Feeds:* =SPC n e= opens elfeed (LINGUIST List + Language Log). =G= refresh,
  =RET= read, =s= filter.

* Converting & running things
:PROPERTIES:
:CUSTOM_ID: tools
:END:

=SPC l= opens the launch/convert menu.

- *Convert the current file:* =w= → Word, =h= → HTML, =p= → PDF. Org/Markdown use
  *Quarto's bundled pandoc* (=quarto pandoc=; PDF via Typst — no LaTeX, no
  separate pandoc needed); =.qmd= uses =quarto render=. =t= compiles a =.typ=
  with Typst.
- *marimo (per-project):* =SPC l m= launches a marimo notebook *in a directory
  you pick, using that directory's uv environment* (=uv run marimo edit=). Runs
  as an Emacs child (=SPC l P=), so quitting Emacs stops it.
- *Services:* =SPC l s= opens *prodigy* — start/stop/see status of long-running
  services (marimo on :2718 — needs =uv tool install marimo= once; BentoPDF on
  :3000). =s= start, =S= stop, =r= restart, =b= open its URL (shown in the name).
- *What did I leave running?* =SPC l s= (services) and =SPC l P=
  (=list-processes=, all Emacs child processes). Everything launched this way
  dies when Emacs quits.

* Read-aloud & dictation (Linux)
:PROPERTIES:
:CUSTOM_ID: readback
:END:

Reads *continuously from the current paragraph to the end of the section*
(pocket-tts), synthesizing ahead so it doesn't pause between paragraphs. Pause to
*speak a comment*: it's transcribed (Parakeet v3) and inserted as an Org =#=
comment under the paragraph being read, then reading resumes. Comments don't
export to Word. Works in *Org, Markdown and QMD*. Enable with =SPC t R=; enabling
loads the speech models, disabling frees them.

** Controls (while the mode is on)
:PROPERTIES:
:CUSTOM_ID: readback-controls
:END:

| Key       | Action                                                          |
|-----------+-----------------------------------------------------------------|
| =<f4>=    | Render this section to audio, then unload the TTS model          |
| =M-<f4>=  | Render the *whole file* to audio, then unload the TTS model      |
| =<f5>=    | Cycle the voice (for the current language)                       |
| =<f6>=    | Switch language English ⇄ Spanish                                |
| =<f7>=    | Read from the current paragraph to the section end (model hot)   |
| =<f8>=    | Dictate: once = *pause + record*, again = *stop + insert + resume* |
| =<f9>=    | Pause / resume                                                   |
| =M-<f9>=  | Stop the read-through                                            |
| =<f10>= / =<f12>= | Previous / next paragraph                               |
| =M-<f10>= / =M-<f12>= | Slower / faster (0.5×–3.0×, remembered)             |
| =C-<f12>= | Reset speed to 1.0×                                              |

A live *header-line* at the top shows =🎙 Dictation — EN/ES= while the mode is on.
Comments *stack* below existing ones and use the right format per file: Org
=# …=, Markdown/QMD =<!-- … -->= (both invisible to Word export). It works in
*Org, Markdown and QMD* — sections split on headings (Org =*=, Markdown/QMD =#=).

*Two ways to read:* =<f7>= keeps the model in memory and synthesizes as it goes
(snappiest for back-and-forth); =<f4>= renders the whole section once and then
*frees the TTS model* (lighter if you're reading a file just once). Spanish uses
=lola=, English =alba= (cycle with =<f5>=).

* Windows, panes & jumping around
:PROPERTIES:
:CUSTOM_ID: windows
:END:

Emacs calls the split areas *windows* (what other apps call panes); the things
they show are *buffers*. Quick vocabulary: splitting makes more windows;
switching buffers changes what a window shows.

** Split & close
- =SPC w= opens the windows menu: =s= split below, =v= split right, =o= other
  window, =d= delete this window, =m= maximize (only this one), ~=~ balance.
- Or the classic keys: =C-x 2= split below, =C-x 3= split right, =C-x 1= only
  this window, =C-x 0= close this window.

** Jump between windows (the Alt-Tab you wanted)
- =C-x o= (or =SPC w o=) = *other window* — cycles focus to the next window.
  With two windows open it just toggles between them, like Alt-Tab.
- =q= does *not* switch windows — in read-only/special buffers (help, dired,
  magit) =q= buries/closes that buffer. That's probably what confused you.

** Switch what a window shows (buffers)
- =SPC ,= (=consult-buffer=) or =C-x b= — pick another buffer to display here.
- =SPC k= kills the current buffer; =C-x C-s= saves it.

** Jump to a prompt / cancel a command
- Started a command and the prompt is waiting but you clicked away? =C-c j=
  (or =SPC j=) jumps back to the active minibuffer.
- To *cancel* a command from anywhere: =C-]= (abort). Inside the minibuffer,
  =C-g= also cancels.

* Setting up a project
:PROPERTIES:
:CUSTOM_ID: project-setup
:END:

A "project" lets =SPC p= find files, search, and switch within one folder.

- *Easiest:* make the folder a Git repo — =cd folder && git init= (or =SPC g g=
  in a file there, then =I= to init). It's now a project automatically.
- *No Git?* Create an empty file named =.project= in the folder's root. This
  config treats that as a project marker.
- Then: =SPC p p= switch project · =SPC p f= find file in project · =SPC p g=
  grep the project · =SPC p b= switch project buffer · =SPC p d= dired.

* The config workflow (important)
:PROPERTIES:
:CUSTOM_ID: workflow
:END:

- All settings live in =Config.org=. Edit a block, *save* — it auto-tangles to
  =post-init.el=. Restart Emacs (or re-evaluate the block) to apply.
- *Never* hand-edit the =*-init.el= files; they're generated.
- The base (=init.el=, =early-init.el=) is minimal-emacs.d — customise via
  =Config.org=, not those.
- It's a git repo: =SPC g= then =g= for Magit. Commit as you go; pull/push to
  sync your other machine. Note each machine installs its own packages, so
  versions can differ.

Happy writing.
